# 群排行开工准备清单（历史准备基线）

日期：2026-10-26。本文保留最初准备阶段的仓库评估。**用户随后明确取消申请审批，改为核验群来源后直接参与；当前实现与验收以[群内直达规格](../../specs/group-ranking/spec.md)和[当前提案](./proposal.md)为准。下文邀请/审批、P0 未接后端等描述属于历史建议，不是当前工作指令。** 目标微信账号、真机或提审验证仍未完成。

当日 P0 进展：独立 Taro 工程、三种虚构官方模板预览和登录/群入口/隐私状态探针已建立，类型检查和微信包构建通过。开发者工具已使用当前微信快捷登录；用户已手动登录公众平台，但 Browser Use 拒绝该站点，当前无法自动管理基础信息/域名，插件目录搜索未找到可用的专用连接器。目标 AppID、主体及类目尚未确认，后端和真实群闭环未接入。后台自动操作是用户明确要求的后续交付能力，目前仍是阻塞项。

## 1. 已确认与建议

- 用户确认：独立小程序，同一仓库复用技术。
- 推荐技术：Taro/React/TypeScript + NestJS + Prisma/PostgreSQL + 现有 Next 管理台。
- 推荐先做邀请式群空间闭环，自动识别微信群作为增强。
- 推荐 P1 只开放普通数据的官方模板；自定义编辑器、公开投稿和健康数据逐步开放。后面三项是实施建议，不是用户取消需求。
- 同仓库、同技术不代表自动共用账号、角色、隐私同意或真实数据。

## 4. P0：先验证什么

| 验证 | 操作与样本 | 通过条件 | 受限时处理 |
| --- | --- | --- | --- |
| 独立身份 | 新 AppID 登录；旧小程序及管理台凭证请求新接口 | 新身份稳定；错误业务身份拒绝；OpenID 不作为跨产品账号映射依据 | 明确独立身份后再连业务数据 |
| 群入口 | A/B 两群卡片、跨群转发、私聊、扫码、最近使用、冷/热启动、不同设备 | 记录入口场景、API 成败、相同群标识稳定性；加密结果由服务端验证和处理，不信任客户端自报群 ID | 使用内部邀请空间；产品文案不承诺精确识群 |
| 登录态与加密数据 | session 过期、重新登录、篡改数据、重放群来源结果 | 明确绑定与时效、失败处理；原始 session key 或群加密载荷不写普通日志 | 保持群识别关闭；不把群标识当成员授权 |
| 分享邀请 | 复制、跨群转发、撤销、过期、重复申请 | 随机不可猜邀请标识、有效期、审批、频控；转发不泄漏成绩；服务端对状态和权限强校验 | 仅展示安全模板简介/申请入口 |
| 空间隔离 | 改 groupId/boardId/entryId，移除成员后再访问 | 列表、详情、排名、历史、写入均拒绝越权；拒绝响应不包含私有数据 | 隔离测试通过前不导入真实参与者数据 |
| 内容安全 | 标题、描述、字段名、选项、备注；编辑后重测；模拟超时与失败 | 检测结论与内容版本关联；仅通过内容可共享；失败不直接放行，人工处理可追踪 | 限制为受控官方文案；不通过隐藏功能规避审核 |
| 隐私与删除 | 拒绝授权、撤回、删记录、注销；新用户与已有用户 | 实际收集、隐私说明、平台申报一致；撤回后服务端停止相应处理，删除后排行同步更新 | 暂不启用敏感场景 |
| 动态字段与排行 | 用虚构数据覆盖边界、并列、编辑删除、闭榜 | 同 Schema 前后端校验一致；服务端为结果唯一来源 | 限制官方 Schema，暂不开自定义编辑器 |
| 主体/类目与提审 | 管理员核实准入；准备可体验的真实 MVP 与内容安全证据，再单独授权提审 | 记录平台实际反馈；将可用、有限可用、不可用分开，不承诺通过 | 调整类目、功能或主体后再发布 |

P0 不等于必须等待完整上架后才能做本地 P1。账号与平台验证期间可以完成虚构数据原型、契约和权限测试；真实敏感数据采集、上线和提审依赖对应结论与授权。

## 5. 编码前需冻结的契约（建议默认值）

这些是后续设计输入，不是已经实现的行为。

- **成员权限**：owner/admin/member；邀请默认申请审批；最后一名 owner 不能直接退出。成员移除即时生效，已产生历史记录是否保留和如何脱敏要与隐私说明一致。
- **模板**：发布版本不可变；实例固定版本。P1 使用经校验的官方 Schema，不必先做独立 Scenario 表、投稿状态机或迁移编辑器。
- **字段**：一个数值或时长主指标，最多五个辅助字段，至多一个短备注；九种字段类型分期接入。日期/时间先作为辅助，跨午夜的熬夜排名另定义语义。
- **数值**：统一小数精度、单位和可接受范围；时长以整数秒存储；不要直接用浮点相等判断并列；未知字段、重复 key、无效默认值、过长选项在服务端拒绝。
- **排名**：白名单 Latest/Max/Min/Sum/Count/Average，升降序；并列用 1、2、2、4。Count 统计有效记录数，不要求一个数值字段。显示取舍与比较精度需一致。
- **时间**：统一 Asia/Shanghai、周一周起始、区间 `[start, end)`；每个模板固定采用发生时间或提交时间。发生时间使用统一 `occurredAt`，若来自日期字段需显式绑定，避免同时存在两个不一致时间来源。
- **Latest 与历史**：按模板选定的时间确定最新，时间相同用服务端记录 ID 稳定取值；成员同分仍并列。无有效记录者默认不入排名；编辑、删除、违规失效后重算。
- **状态与并发**：空间待加入/有效/移除，榜单开放/暂停/关闭，成绩有效/待处理/删除等状态分开；提交防重复、编辑冲突、删除幂等，明确谁可见什么。
- **治理与隐私**：审核通过和公开上架分开；元数据文案也检测；管理员删除与用户删除原因可审计，但审计日志不复制完整健康数据。未来缓存、导出、备份的删除边界也须定义。

建议最初模型：`GroupRankUser`、`GroupSpace`、`GroupMember`、`GroupInvite`、`Template`、`TemplateVersion`、`Leaderboard`、`Entry`，以及按实际入口需要增加的同意/举报/内容检测/审计记录。表名、索引、外键及状态以数据库设计评审为准；本次不修改 Prisma schema 或 migrations。

## 6. 实施顺序与产出

1. **产品骨架与 P0**：独立 app 最小页面、登录/分享能力探针、两个群隔离测试、主体与类目结论表。交互先覆盖无群、待审批、无成绩、审核中、无权限、闭榜等状态。
2. **契约与测试设计**：数据关系、API/错误码、角色矩阵、字段 Schema、时间/精度规则，整理可执行验收样本。开工前把关键推荐转成明确决定。
3. **P1 完整闭环**：登录 → 创建空间 → 官方模板建榜 → 分享申请/批准 → 提交 → 排名 → 编辑/删除 → 管理员移除。同步接入文本治理与用户删除入口。
4. **P2 玩法编辑器**：增加字段、校验、预览、个人草稿和规则选择；服务端 Schema 继续是权威，版本固定。
5. **P3 公共模板库**：投稿、人工审核、上架/下架、举报、版本、使用统计；示例只用虚构数据。
6. **健康及高级场景**：必要性和隐私影响评估、单独告知/同意、可见范围、撤回删除及资质/审核结论齐备后启用；复杂公式等依反馈再做。

不建议在本轮直接铺开 PRD 中所有实体、缓存和页面。第一份可验收交付应是“独立小程序 + 两群隔离 + 一个官方模板”的真实闭环。

## 7. 文档查证与限制

- 尝试读取[微信 getGroupEnterInfo](https://developers.weixin.qq.com/miniprogram/dev/api/open-api/group/wx.getGroupEnterInfo.html)、[文本内容安全接口](https://developers.weixin.qq.com/miniprogram/dev/OpenApiDoc/sec-center/sec-check/msgSecCheck.html)及[产品资料](https://developers.weixin.qq.com/miniprogram/product/material.html)，本次抓取未成功。因此最新准入类目、接口条件、版本要求、额度及审核可行性均保留为目标账号后台核查项，未引用第三方博客代替结论。
- [国家网信办发布的《个人信息保护法》](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)第二十八至三十条涉及医疗健康信息的敏感属性、处理必要性、单独同意和额外告知；第五十五至五十六条涉及事前个人信息保护影响评估及记录。健康场景需要专项准备，单个同意弹窗不足以完成设计。
- 本次未操作微信公众平台、开发者工具、真实群、数据库或生产系统；未跑业务构建。版本检查和文档检查不代表新小程序已可发布。
